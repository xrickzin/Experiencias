# Conceito, linguagem e princípios de UX

Regras de produto: [../product/product-definition.md](../product/product-definition.md). Precedência: [README.md](./README.md#precedência).

## Conceito central

Laço é um aplicativo para casais viverem, planejarem e preservarem experiências compartilhadas.

Não deve ser percebido como: aplicativo de viagens, gerenciador de tarefas, Kanban, rede social, diário individual, galeria de fotos ou ferramenta corporativa de planejamento.

A experiência central é **Desejo → Planejamento → Vivendo → Memória**. A área **Nossa História** apresenta as experiências que já se tornaram memórias.

> A experiência termina. A memória continua.

## A mesma experiência

Desejo, Planejamento, Vivendo e Memória são estados/contextos da **mesma experiência**. Não criar entidades separadas para desejo, planejamento, experiência ou memória. "Conhecer Campos do Jordão" é a mesma experiência durante toda a evolução.

## Complexidade progressiva

A interface acompanha o envolvimento do casal.

> A complexidade da interface deve acompanhar o grau de envolvimento do casal com a experiência.

Um casal pode iniciar um planejamento e adicionar só a data; outro pode adicionar data, localização e mais. Ambos são válidos. Não criar campos obrigatórios sem necessidade.

## Princípios de UX

1. **A experiência pertence aos dois.** Ambas as pessoas editam informações gerais e registros compartilhados.
2. **Algumas partes pertencem a cada pessoa.** Impressão e momento favorito são individuais.
   > A experiência pertence aos dois. Os registros pertencem à experiência. Impressões e momentos favoritos pertencem individualmente a cada pessoa.
3. **Sem gerenciador de tarefas.** O produto ajuda o casal a viver experiências, não cobra produtividade.
4. **A interface cresce junto com a experiência.** Uma ideia simples pode permanecer simples.
5. **Não exigir informação só para preencher interface.** O que é opcional no produto permanece visualmente opcional.
6. **Fotografia é protagonista, mas não é requisito.** Memórias sem fotos são válidas.
7. **O fio conecta; o laço marca.** O fio vermelho é recorrente; o laço aparece nos momentos especiais ([visual-identity.md](./visual-identity.md)).

## Linguagem geral

Preferir linguagem humana, simples, direta, afetiva e contemporânea. Evitar linguagem corporativa, técnica, excessivamente romântica, infantil ou burocrática.

| Preferir | Em vez de |
|---|---|
| **O que queremos viver** | Lista de desejos |
| **Começar planejamento** | Alterar status para planejamento |
| **Guardar este momento** | Adicionar registro |
| **Nossa História** | Arquivo de memórias |

Não presumir a natureza da relação (namorado, marido, parceira…): o produto é para casais e a linguagem não precisa ir além disso.

## Princípios acima das decisões visuais

Qualquer que seja a solução visual escolhida pelas skills de design ([design-direction.md](./design-direction.md)), estes princípios permanecem:

1. **O casal é o centro.** Laço é um aplicativo para casais.
2. **A experiência é a entidade central.** Não transformar o produto em um conjunto de tarefas.
3. **Os estados pertencem à experiência** (Desejo, Planejamento, Vivendo, Memória).
4. **Complexidade progressiva.**
5. **Não forçar documentação.** Registrar é possibilidade, não obrigação.
6. **Memória é preservada.** Não volta para Vivendo.
7. **Datas não são inventadas.** A precisão temporal escolhida pelo casal é preservada.
8. **Não parecer gerenciador de tarefas.** Planejar não é transformar o relacionamento em checklist.
9. **Não parecer rede social.** Sem feed, curtidas, ranking ou métricas sociais.
10. **Simplicidade.** Nenhuma decisão visual justifica uma funcionalidade de que o produto não precisa.
